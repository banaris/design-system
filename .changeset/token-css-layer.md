"@banaris/design-system": minor
---

`styles.css` no longer overrides a consumer's Tailwind theme. The design tokens now sit in `@layer theme.ds`, a sublayer of `theme`, instead of outside every layer, so a consumer's own `@theme` (for example `--color-accent`) wins whichever stylesheet they import first. The 14 tokens that reused Tailwind's stock names with different values are renamed so that neither side changes the other: `--radius-{xs,sm,md,lg}` → `--radius-ds-*` (`rounded-ds-*`), `--text-{xs,sm,base,lg}` and their `--line-height` → `--text-ds-*` (`text-ds-*`), `--font-sans` / `--font-mono` → `--font-ds-sans` / `--font-ds-mono`. The package's components use the new names, so they keep their radius, type scale and typeface in a Tailwind consumer, and the consumer's `rounded-md`, `text-sm` and `font-sans` are no longer changed. If your own CSS read `var(--radius-md)`, `var(--text-sm)` or `var(--font-sans)` from `styles.css`, switch to the `-ds-` names. `theme.css` (for consumers who run their own Tailwind) still declares the old names, now as aliases of the new ones, and ships as three files: `tokens.css`, `variants.css` and `stock-aliases.css`. To override a colour that has a separate dark value, set the dark value too (see the README). Under `prefers-reduced-motion: reduce`, `styles.css` now actually zeroes the `--duration-*` tokens (the tokens used to outrank the rule that does it, so components kept animating).
